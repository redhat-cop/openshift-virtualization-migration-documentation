This page is a **run sheet** for a Services Consultant on a **customer bring-your-own** environment. It is not a second copy of the journey. Follow the steps here; open the linked journey pages when you need the full procedure.

== What you will finish

With basic OpenShift Virtualization knowledge (Ansible and MTV may be new):

* Confirm the customer environment is ready for Migration Factory (Gate 0).
* Stand up Migration Factory on that environment (inventory → validate → seed).
* Migrate **one** powered-off **RHEL 9** VM from **VMware** to **OpenShift Virtualization** using **MTV + AAP + Migration Factory** (**cold** plan).
* Validate: MTV plan **Succeeded**, VM **Running**, guest has an IP, and a **ping** smoke test succeeds.

This path does **not** cover warm migration, Windows guests, RHV sources, or multi-VM waves. Use the main journey for those.

== Suggested steps

Complete these in order. Do not skip Gate 0.

. Confirm access and version floors, then pick the RHEL 9 VM.
. Pass **every** item in Gate 0 (commands below).
. Finish prepare: inventory → xref:journey:validate-environment.adoc[Validate your environment] → xref:journey:seed-aap.adoc[seed AAP].
. Configure providers, then storage and network maps.
. Power off the VM, define a one-VM cold wave, start the plan in MTV, wait for **Succeeded**.
. Start the VM on OpenShift Virtualization, confirm IP, run a ping smoke test.
. Send feedback through xref:support:channels.adoc[Support] if something blocked you.

Gate 0 failures usually cost more than the migration itself — fix them before you seed.

== Assumptions

* **Audience:** Services Consultant; OpenShift Virtualization basics; may be new to AAP and MTV.
* **Environment:** Customer BYO (no shared lab for this guide).
* **Source:** VMware vSphere with one RHEL 9 VM you are allowed to power off.
* **Destination:** OpenShift cluster with OpenShift Virtualization and MTV already installed.
* **Automation:** Ansible Automation Platform available (existing or deployed as part of prepare).

Version floors from the enablement story (confirm against the customer platform and current collection support):

* vSphere 7.0+
* OpenShift 4.18+
* AAP 2.5+
* MTV 2.6+

Full access and credential checklist: xref:journey:prerequisites.adoc[Prerequisites].

== Pick the VM

Choose **one** RHEL 9 VM that:

* You may power off for a cold migration.
* Has a stable name you will put in the wave request.
* Answers **ping** from a host you will use after cutover (or will after you start it on OpenShift Virtualization), so the smoke test is meaningful.
* Is not the only path to a critical production service for this sitting.

On vSphere, note the VM name (and folder/path if you will identify it that way). You will power it off before you start the plan.

== Gate 0 — ready for Migration Factory?

Pass **every** checkbox before you continue. If any item fails, stop, fix it, and re-check. Do not seed to paper over a missing operator. This gate matches xref:journey:validate-environment.adoc[Validate your environment]; the commands below are a CLI path to the same checks.

=== Checklist

* [ ] OpenShift Virtualization operator Succeeded; VM APIs exist
* [ ] MTV operator Succeeded; *Migration* appears in the OpenShift console
* [ ] You can log in to AAP at the inventory hostname
* [ ] Inventory has the three groups, no leftover `changeme`, and `vm_sources` names match hosts (xref:journey:configure-inventory.adoc[Building your inventory])
* [ ] Execution environment pull works for the Migration Factory EE image

=== How to check each item

==== OpenShift Virtualization

Logged in to the destination cluster:

[,shell]
----
oc get csv -A | grep -iE 'virt|kubevirt|openshift-virtualization'
oc api-resources | grep -i kubevirt
----

Expect a Succeeded CSV (or equivalent) and VirtualMachine-related API resources.

==== MTV

[,shell]
----
oc get csv -A | grep -iE 'mtv|forklift|migration-toolkit'
oc get forkliftcontrollers.forklift.konveyor.io -A
----

Expect a Succeeded CSV and a Forklift controller. In the console, confirm *Migration* lists Providers and Plans.

==== AAP login

Replace the hostname with your `aap_hostname`:

[,shell]
----
curl -kI "https://<aap_hostname>/"
----

Expect an HTTP response (not a connection error). Then open the same URL in a browser and sign in with the account from the inventory.

==== Inventory file

From the directory that holds your inventory file:

[,shell]
----
grep -n 'changeme' inventory.yml || echo 'No changeme placeholders'
grep -E '^\s*(migration_aap|migration_clusters|vm_sources):' inventory.yml
----

Expect no `changeme` values you still need to replace, and the three group names present. Confirm by eye that every name under each cluster's `vm_sources` exists as a `vm_sources` host.

==== Execution environment

[,shell]
----
podman login quay.io/redhat-cop
podman pull quay.io/redhat-cop/openshift-virtualization-migration-ee:latest
----

If jobs run only from AAP, configure the registry credential on AAP instead and confirm a test job can pull the same image. See xref:journey:source-collection.adoc[Sourcing the collection and execution environment].

When every box in the checklist is checked, continue. Next detailed pass after the inventory is finished: xref:journey:validate-environment.adoc[Validate your environment], then xref:journey:seed-aap.adoc[Seeding Ansible Automation Platform].

== Run the quick start

=== 1. Prepare the environment

Work through xref:journey:setup-environment.adoc[Preparing your environment] in order, stopping after validate:

. xref:journey:prerequisites.adoc[Prerequisites]
. xref:journey:migration-factory-prerequisites.adoc[Migration Factory prerequisites] (only if you still seed or install AAP from a laptop)
. xref:journey:source-collection.adoc[Sourcing the collection and execution environment]
. xref:journey:confirm-openshift-ready.adoc[OpenShift] — Virtualization and MTV already installed
. xref:journey:setup-aap-yourself.adoc[Ansible Automation Platform] **or** xref:journey:setup-existing-ocp.adoc[Deploying Ansible Automation Platform] if AAP is not installed yet
. xref:journey:configure-inventory.adoc[Building your inventory]
. xref:journey:validate-environment.adoc[Validate your environment] — Gate 0 again on the finished inventory

=== 2. Seed Ansible Automation Platform

. xref:journey:seed-aap.adoc[Seeding Ansible Automation Platform]
. In AAP, confirm the Migration Factory templates exist (Provider, Maps, Plans, and the Migrate template used only as a seed check).

=== 3. Providers and maps

. xref:journey:create-providers.adoc[Configure providers] — one VMware source to this OpenShift target; green check in MTV.
. xref:journey:create-maps.adoc[Configure storage and network maps] — maps **Ready** for that pair.

=== 4. Prepare the guest for a cold plan

. xref:journey:prepare-vms.adoc[Preparing VMs for migration] — maintenance window; VMware Tools as required by MTV.
. On vSphere, **power off** the RHEL 9 VM. Cold plans expect the source off for the cutover sitting.

=== 5. Define a one-VM cold wave

. xref:journey:prepare-migration-wave.adoc[Defining a migration wave]
. Launch **OpenShift Virtualization Migration - MTV Plans** from AAP.
. Use a request with a single VM and a **cold** plan (cold is the default when you do not set warm). Example shape — replace names with the customer pair and VM:

.quick-start-wave.yml
[source,yaml]
----
mtv_plans_migration_request:
  source: <mtv-provider-name>           # RFC 1123 form after Configure providers
  destination: host
  target_namespace: <project-for-vms>
  network_map: <source>-host            # or the names from Create maps
  storage_map: <source>-host
  verify_plans_ready: true
  plan_name: quickstart-rhel9-cold
  vms:
    - name: <rhel9-vm-name>
----

. Confirm the Plan CR is **Ready** in *Migration* → *Plans for virtualization*.

[NOTE]
====
Survey `source_name` / `target_name` are inventory host names. Provider and map names in `mtv_plans_migration_request` are MTV names. See the wave page if those disagree.
====

=== 6. Start the migration in MTV

. xref:journey:execute-migration.adoc[Migrating VMs]
. Start the **Ready** plan in the OpenShift console. Do **not** expect the AAP **Migrate** template to copy disks.
. Wait until the plan is **Succeeded** (cold finishes in the same run as **Start**; no separate cutover).

=== 7. Validate

. xref:journey:verify-migration.adoc[Verifying a migration]
. Plan status **Succeeded**.
. Open the VirtualMachine in `target_namespace`. MTV leaves it **Stopped** — *Actions* → *Start* → wait until **Running**.
. Confirm the guest has an IP (console, guest agent, or `oc` / VM details), then ping it from a host that can reach that address:
+
[,shell]
----
oc get vmi -n <target-namespace>
ping -c 3 <guest-ip>
----
+
Success on **ping** means the NIC and route you mapped are good enough for this first sitting.

[NOTE]
====
Deeper application checks are out of scope for this quick start. If ping fails, fix network map / NAD / firewall before you call the sitting done.
====

=== 8. Close the sitting (optional)

. xref:journey:close-migration-wave.adoc[Closing the migration wave] and xref:journey:archive-plan.adoc[Archiving the plan] when the customer process requires it.

== Done when

* [ ] Gate 0 passed before seed
* [ ] One RHEL 9 VM cold-migrated from VMware via MTV + AAP + Migration Factory
* [ ] MTV plan **Succeeded**
* [ ] VM **Running** on OpenShift Virtualization with an IP
* [ ] Ping smoke test succeeded

== If you get stuck

[cols="1,2"]
|===
| Symptom | Where to look

| Operator or MTV menu missing
| xref:journey:confirm-openshift-ready.adoc[OpenShift], Gate 0

| Seed fails / EE pull fails
| xref:journey:seed-aap.adoc[Seeding Ansible Automation Platform], xref:journey:source-collection.adoc[Sourcing the collection and execution environment]

| Provider not green
| xref:journey:create-providers.adoc[Configure providers]

| Plan never **Ready**
| xref:journey:prepare-migration-wave.adoc[Defining a migration wave], maps and VM name

| AAP Migrate job green but disks never move
| Expected — start the plan in the console (xref:journey:execute-migration.adoc[Migrating VMs])

| Plan **Succeeded**, VM missing or wrong project
| Check `target_namespace` (xref:journey:verify-migration.adoc[Verifying a migration])

| VM Running but ping fails
| Network map / guest firewall / routing; revisit xref:journey:create-maps.adoc[Configure storage and network maps]
|===
